# Vortex — пользовательская часть MVP

## Что уже было в проекте
- FastAPI отдаёт Mini App и `/api/orders`, проксируя каталог ai-product через `CatalogClient`.
- Публичная схема карточки уже ограничена безопасными полями; API-ключ остаётся на сервере.
- Была базовая Mini App с категориями, поиском и пагинацией.
- Был Telegram-бот с `/start`, кнопкой открытия Mini App и пересылкой `channel_post` в существующий вебхук ai-product.

## Что добавлено
- Карточки заказов с открытием экрана подробностей и переходом к оригинальной публикации.
- Избранное в `localStorage` браузера/Telegram Mini App.
- Сортировка по дате и названию, фильтр избранного, улучшенный поиск.
- Адаптация интерфейса под узкие мобильные экраны, безопасные области, состояния загрузки/ошибки/пустого списка.
- Telegram-бот: `/start`, меню, открытие Mini App, включение/выключение уведомлений, `/subscribe`, `/unsubscribe`.
- Фоновая проверка уже существующего каталога через `CatalogClient` и уведомления о новых ID. Сбор заказов и ИИ не дублируются.

## Запуск
1. Установить зависимости: `pip install -r requirements.txt`.
2. Скопировать `.env.example` в `.env`.
3. Для разработки интерфейса без подключения ai-product установите `VORTEX_DEMO_MODE=true`. Тогда `/api/orders` отдаёт локальные тестовые карточки в том же формате API.
4. Запустить API: `uvicorn main:app --host 127.0.0.1 --port 8001`.
5. Открыть `http://127.0.0.1:8001`.
6. Telegram-бот и публичный HTTPS URL настраиваются отдельно, когда будете готовы проверять Telegram.

Для реального каталога `VORTEX_DEMO_MODE` должен быть `false`; подключение `PRODUCT_API_BASE_URL` и `PRODUCT_API_KEY` выполняет ответственный за ai-product. Контракт `/api/orders` не меняется.

## Контракт API
Mini App использует существующий `GET /api/orders?limit=20&offset=0`. Формат ответа и upstream-интеграция не менялись. Подробный экран показывает поля, уже доступные в публичной карточке; полный текст задания открывается по ссылке оригинала, потому что `/api/orders` сейчас не отдаёт отдельное поле полного описания.

## Уведомления
Подписка пользователя выключена по умолчанию и включается кнопкой в боте или командами `/subscribe` и `/unsubscribe`. Проверка выполняется с интервалом `VORTEX_NOTIFY_INTERVAL` (по умолчанию 90 секунд). При первом запуске бот фиксирует текущие последние 100 заказов как уже известные, чтобы не отправлять массовую рассылку старых публикаций. Подписчики и отправленные ID хранятся в существующей SQLite базе Vortex.

## Важно
- Реальные платежи не добавлялись.
- Никакие endpoints или поля API не менялись.
- Для production Mini App нужен HTTPS URL и корректная настройка домена в Telegram/BotFather.
- Не включайте в репозиторий `.env`; используйте `.env.example` как шаблон.

## Обновления интерфейса: избранное и профиль

- В Mini App появилась верхняя навигация: «Заказы», «Избранное», «Профиль».
- Вкладка «Избранное» показывает сохранённые карточки отдельно от общей ленты. Список хранится в localStorage этого браузера/устройства.
- Вкладка «Профиль» показывает Telegram-имя, username и ID, когда приложение открыто внутри Telegram.
- В Telegram-боте `/start` предлагает регистрацию кнопкой. `/register` создаёт/обновляет профиль в локальной SQLite-базе Vortex, `/profile` показывает его. Кнопка «Мой профиль» доступна в меню.
- Регистрация использует только данные Telegram-профиля; пароль и отдельная учётная запись не создаются.

Для обновления существующей установки остановите сервер и бота (`Ctrl+C` в их терминалах), распакуйте архив поверх папки проекта с заменой файлов, не удаляя свой `.env` и базу `database/freelance.db`. Затем запустите сервер и бота обычными командами из инструкции выше. Для Telegram Mini App по-прежнему нужен публичный HTTPS URL в `VORTEX_WEBAPP_URL`.


## Регистрация, профиль и серверное избранное

- `GET /api/me` автоматически создаёт профиль при первом валидном входе через Telegram Mini App и возвращает существующий профиль при следующих входах.
- `PUT /api/me` обновляет специализацию, навыки, категории и бюджетные предпочтения.
- `GET /api/favorites`, `POST /api/favorites`, `DELETE /api/favorites/{order_id}` управляют избранным пользователя.
- Все пользовательские endpoints проверяют подпись Telegram `initData` на сервере через `TELEGRAM_BOT_TOKEN`; `initDataUnsafe` не используется для авторизации.
- Mini App отправляет `X-Telegram-Init-Data` автоматически. Обычный браузер без Telegram WebApp не может создать авторизованный профиль.
- Профиль и избранное привязаны к Telegram ID и готовы для будущей персонализации ИИ. Новые endpoints не меняют контракт `/api/orders`.

### Переменные окружения и Render

Добавьте `TELEGRAM_BOT_TOKEN` в Environment сервиса Render (значение не публикуйте). В BotFather настройте Mini App на публичный HTTPS URL сервиса. `VORTEX_DEV_AUTH` оставляйте выключенным в production.

Для постоянного хранения профилей и избранного на Render рекомендуется подключить Render PostgreSQL и задать `DATABASE_URL` в Environment. Код поддерживает PostgreSQL через `psycopg`; если `DATABASE_URL` не задан, используется локальный SQLite `database/freelance.db` (для production на эфемерном диске Render это не является надёжным постоянным хранилищем).

Локальная проверка без Telegram: временно задайте `VORTEX_DEV_AUTH=true` только в локальном терминале. Не переносите этот флаг на Render. Для тестовых заказов дополнительно можно задать `VORTEX_DEMO_MODE=true`.
